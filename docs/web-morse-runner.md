# Vendored Web Morse Runner

The tracker uses a pinned, locally hosted copy of
[Web Morse Runner](https://github.com/fritzsche/WebMorseRunner), written by
Thomas Fritzsche, DJ1TF. The frame entry point is `/vendor/web-morse-runner/`.
It is a public static simulator, not a separate account or authentication system.
The private tracker owns practice history and synchronization.

## Ownership and layout

| Path | Ownership |
| --- | --- |
| `scripts/web-morse-runner/approved.json` | Reviewed upstream commit and SHA-256 hashes |
| `scripts/web-morse-runner/update.mjs` | Fetching, exact patch contracts, generation, offline verification |
| `public/vendor/web-morse-runner/upstream/` | Generated byte-exact upstream runtime sources and license; never hand-edit |
| `public/vendor/web-morse-runner/runtime/` | Generated runtime with documented path/storage-key patches; never hand-edit |
| `public/vendor/web-morse-runner/index.html` | Generated frame shell preserving upstream DOM IDs |
| `public/vendor/web-morse-runner/integration/` | Locally maintained theme and adapter; updater never writes here |
| `public/vendor/web-morse-runner/data/synthetic-calls.txt` | Generated original practice strings, not copied registry data |
| `public/vendor/web-morse-runner/UPSTREAM.json` | Generated provenance, source/output hashes, patches and exclusions |

The reviewed revision is
[`847e9089ef379a065d1cf6807c09f0724bbe072e`](https://github.com/fritzsche/WebMorseRunner/tree/847e9089ef379a065d1cf6807c09f0724bbe072e)
(upstream v0.19.1 beta). Runtime files are copied unchanged first; a second copy
receives four small adjustments: module-relative AudioWorklet loading, the
synthetic calls URL, namespaced settings/calls storage, and a generated HTML shell
that loads the local adapter/theme and displays attribution. Raw source remains
available for straightforward comparison with upstream.

Raw `index.html` is stored as `upstream/index.html.txt` so it is not a second
runnable app. Hash metadata retains its original upstream filename. The generated
frame shell is marked `noindex, nofollow` and `data-pagefind-ignore`.

The iframe isolates DOM, CSS, keyboard handlers, and application lifecycle from
the tracker. **A same-origin iframe is not a security sandbox** and does not
prevent access to same-origin storage. Treat vendored code as reviewed site code.
Do not describe `allow-scripts` plus `allow-same-origin` as a security boundary.
A genuinely isolated origin is a separate hosting decision, not part of this
vendor workflow.

## Reproduce and verify

Regenerate the currently approved revision with its explicit full SHA:

```sh
mise run cw-training:update-runner -- 847e9089ef379a065d1cf6807c09f0724bbe072e
```

Verify everything generated without network access:

```sh
mise run cw-training:update-runner -- --check
node --test tests/web-morse-runner-vendor.test.mjs
```

Generation checks existing output before fetching, then validates all downloaded
source hashes, import dependencies, and exact patch anchors before writing any
output. It rejects changed/missing/unknown generated files rather than silently
discarding local work. It does not delete files. Local `integration/` files are
outside the generated manifest and must be reviewed/tested separately. An
interrupted write leaves a detectable mismatch; inspect and restore only the
affected generated files before retrying, without removing local integration work.

## Deliberate upgrades

1. Choose a full upstream commit SHA, not `main`, a tag, or a short hash.
2. Run `mise run cw-training:update-runner -- --inspect FULL_SHA`. This downloads
   the explicitly enumerated runtime, checks its patch/import contracts, and
   prints candidate hashes. It does not approve or write the revision.
3. Review the upstream diff, license/data notices, timing and scoring behavior,
   and adapter entry points. New modules or changed patch anchors require an
   explicit updater/adapter change and regression tests. Passing anchor checks
   alone does not prove semantic compatibility.
4. Update `scripts/web-morse-runner/approved.json` with the reviewed SHA/hashes,
   then run the explicit-SHA update command. Re-run the offline check and tests.
5. Verify Single Call and WPX assignments in a browser, including keyboard input,
   user-activated audio, partial/completed runs, final results, hidden tabs, and
   no duplicate practice credit. Run the normal site validation before deployment.

No automatic remote-code updates occur at page load, build time, or deployment.
If the new revision changes integration contracts, stop and review; do not add a
force flag that bypasses hashes or compatibility checks.

## License and practice data

Upstream is released under the
[Unlicense](https://github.com/fritzsche/WebMorseRunner/blob/847e9089ef379a065d1cf6807c09f0724bbe072e/LICENSE),
which permits copying, modification, and redistribution. The original license is
kept at both the frame root and in the raw source copy; the UI retains upstream
credit. Our adapter/theme are separate from the upstream engine.

The optional `Example_Calls/` collection is not vendored. Some lists identify
third-party databases, whose redistribution terms were not established. The
default upstream `calls.txt` also lacks a provenance header, so it is not copied.
Instead, `syntheticCalls()` creates 512 deterministic, unique practice strings
from a fixed seed and simple callsign-shaped prefixes/suffixes. This list is
original generated data, not evidence that stations exist or hold particular
licenses. Coincidental matches to real callsigns are possible. These simulated
contacts must never be represented as on-air contacts or uploaded as actual logs.

The original upstream HTML in `upstream/index.html.txt` is retained solely for
source comparison; the supported entry point is the generated frame root. The
adapter should restrict the normal tracker experience
to its supported exercises. Settings and user-selected call data live only in
the simulator's namespaced browser storage; importing instructor data remains an
explicit user action, not an automatic third-party dataset refresh.

## Integration contract boundaries

The generated frame loads `integration/main.js`, which can import `View` from
`../runtime/view.js` and initialize it with `onLoad()`. That adapter must use a
small, validated parent-message protocol rather than exposing the parent tracker
to arbitrary simulator commands or scraping DOM score strings. Keep authentication
credentials and private course content out of the frame.

The upstream engine has no durable contest-state restore or public integration
API. Starting a new contest clears the log/transcript; stopping closes its audio
context. Adapter timing must use cumulative engine seconds, not add a second
parent stopwatch, and must distinguish a complete uninterrupted assigned run
from multiple partial attempts. The parent remains responsible for saving
practice once and preserving the existing required-versus-extra-review rules.
